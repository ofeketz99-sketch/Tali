# אתר ההורדה של Tali

אתר סטטי פשוט: לוגו, שם גדול, כפתור הורדה אחד, ו"מה חדש" (שלוש הגרסאות האחרונות) מתחת. הרקע הוא אותם גלים רכים כמו במסך הבית של האפליקציה, עם כניסה עדינה של הלוגו והשם. אין JavaScript, ו־`prefers-reduced-motion` מכבה את כל התנועה.

## פיתוח מקומי

- הקבצים ב־`website/`; הלוגו ב־`website/assets/logo.png`.
- פתחו `website/index.html` בדפדפן, או: `python -m http.server 8080 --directory website`.
- **עדכון "מה חדש" וגרסה:** אחרי שמוסיפים גרסה ל־`CHANGELOG.md` מריצים `npm run site:notes`. הסקריפט (`tools/site-notes.js`) כותב מחדש את הקטעים שבין `NOTES:START` ל־`NOTES:END` ואת מספר הגרסה בין `VERSION:START` ל־`VERSION:END`. נקודות פנימיות של פיתוח (נבדק, רקע, ערוץ פיתוח וכו') מדולגות, ורק המשפט הראשון של כל נקודה מוצג. אפשר לשנות את הכללים בראש הסקריפט.

## ענפי Git ו-Netlify

- `main`: ענף האתר הראשי; Netlify מפרסם אותו בכתובת הרגילה.
- `dev`: ענף הפיתוח (אותיות קטנות, בדומה ל-RONNY); Netlify מפרסם אותו אוטומטית בכתובת נפרדת `dev--<site-name>.netlify.app`.
- מפתחים ושומרים שינויים ב-`dev`, וממזגים ל-`main` רק כאשר הגרסה מוכנה לפרסום.
- הגדרת Netlify: Production branch = `main`, Branch deploys = `dev` בלבד. אפשר לכבות Deploy Previews כדי להימנע מבניות נוספות שאינן נדרשות.
- אין פקודת `ignore` ב-`netlify.toml` שחוסמת את פריסות `dev`. כל push ל-`dev` עשוי להפעיל פריסה ולצרוך קרדיטים ב-Netlify. פיתוח מקומי אינו מחייב פריסה.
- ענף `DEV` (באותיות גדולות) הוא ענף ישן שנוצר בתחילה. העבודה החדשה באתר צריכה להתבצע ב-`dev` בלבד.
