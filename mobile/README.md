# TALI Mobile

אפליקציית Companion לטלפון: קריאה, כתיבה בסיסית ושרטוט במגע, במסמכים של Tali. לא גרסה מוקטנת של הדסקטופ.

## מה קיים (שלב 1, 17.11.2026)

- **PWA** (אפליקציית רשת שמותקנת למסך הבית): `npm run mobile:build` בונה ל־`mobile/www` (מחוץ ל־Git). `npm run mobile:serve` בונה ומגיש ב־`http://localhost:8090`.
- **עובד בלי אינטרנט:** המסמכים ב־IndexedDB בטלפון (`src/store.js`), וקבצי האפליקציה במטמון של service worker (`sw.js`).
- **רשימת מסמכים:** "נערכו לאחרונה", תיקיות, חיפוש בשם ובתוכן, מסמך חדש (עם `created:` כמו בדסקטופ, `withCreated`), שינוי שם, מחיקה, שיתוף הקובץ, ייבוא קבצים או תיקייה שלמה.
- **עורך:** אותו `createEditor` של הדסקטופ, ולכן אותה שמירה נאמנה לאובסידיאן. סרגל בתחתית, מעל המקלדת: ביטול/חזרה, מודגש, נטוי, קו תחתון, כותרת (H2 ← H3 ← פסקה), רשימה, משימות, מרקר, טבלה, שרטוט.
- **לקריאה בלבד בטלפון** (נשמרים בקובץ כמו שהם): נוסחאות (לחיצה לא פותחת עריכה), מאפיינים (YAML), ידית ⋮⋮, כלי התמונה וסרגל הטבלה. טבלה: עריכת טקסט בתאים בלבד.
- **שרטוט:** שכבת הדף של הדסקטופ (`page-overlay.js`), באותו פורמט `TALI-OVERLAY` ובאותו `pageWidth`, עם כפתורים גדולים לאצבע. שרטוט מהטלפון מוצג במחשב, ולהפך.
- **ערכת צבעים:** ערכות ברירת המחדל של הדסקטופ (`deriveVars`), יום או לילה לפי הטלפון.
- **מנוע סנכרון** (`src/sync-core.js`, עם בדיקות ב־`tests/mobile-sync.test.mjs`): לכל קובץ נשמרים `baseHash` (התוכן בטלפון) ו־`baseRev` (הגרסה במקור) מהסנכרון האחרון, וכך ידוע מי שינה. **אף צד לא נדרס:** כששניהם שינו, הגרסה מהמקור נשארת בשם המקורי, והגרסה מהטלפון נשמרת לידה, `שם (גרסה מהטלפון HH-MM).md` (כמו "גרסה מבחוץ" בדסקטופ). מחיקה בצד אחד אחרי עריכה בצד השני: העריכה מנצחת. הסנכרון רץ כשיש חיבור, אחרי שמירה, בחזרה לאפליקציה וכשהרשת חוזרת.

- **שאלות בתוך האפליקציה (22.11.2026):** שם למסמך חדש, שינוי שם, אישור מחיקה ויצירת מסמך מקישור עוברים דרך `ask()` ב־`app.js` (גיליון תחתון `#mAsk`), ולא דרך `prompt`/`confirm` של הדפדפן. אלה חוסמים, לא נראים כמו האפליקציה, ובחלק מהמעטפות (Capacitor, תצוגה מקדימה) לא קיימים בכלל. שאלה חדשה: רק דרך `ask`.
- **עודכן לליבה של 11.5** (22.11.2026): הענף הועבר מ־10.6 ל־11.5; הבנייה, הבדיקות ועריכה בהדמיית טלפון (375×812) עובדות בלי שינוי בקבצי ה־Core.

## סנכרון עם Google Drive (22.11.2026, לבחירת המשתמש)

הכספת כבר ב־Google Drive (Drive למחשב מסנכרן אותה לדסקטופ), ולכן הטלפון מסנכרן ישירות מול אותה תיקייה ב־Drive. אין שרת של Tali באמצע.

- **`src/drive.js`** (עם בדיקות ב־`tests/mobile-drive.test.mjs`, מול Drive מדומה): המתאם לממשק של `runSync`. `rev` הוא `md5Checksum` של Drive. מה נכנס לטלפון (`shouldSync`): `.md` ו־`.canvas` תמיד, תמונות עד 10MB; PDF וקבצים אחרים נשארים במחשב. לא נכנסים: תיקיות וקבצים שמתחילים בנקודה (`.obsidian`, `.trash`, `.tali.json`), ומסמכי Google Docs. **מחיקה בטלפון מעבירה לסל של Drive**, לא מוחקת לצמיתות. `list()` מחזיר רשימה שלמה או נכשל (רשימה חלקית הייתה מוחקת בטלפון קבצים שלא נקראו). טקסט נקרא בלי להסיר BOM ובלי לשנות CRLF, כך שהעלאה חוזרת לא משנה קובץ שלא נערך.
- **`src/drive-auth.js`, `oauth.html`, `oauth.js`:** התחברות OAuth בזרימת token (בלי client secret ובלי ספרייה חיצונית). חלון קופץ של Google, שחוזר ל־`oauth.html`, והתשובה עוברת לאפליקציה ב־`localStorage` (Google מנתק את `window.opener`). חלון קופץ חסום: הדף כולו עובר ל־Google וחוזר. ה־`state` נבדק, והטוקן נמחק מהכתובת ומההיסטוריה.
- **הטוקן תקף כשעה.** סנכרון ברקע עם טוקן שפג לא פותח חלון: כפתור הסנכרון נצבע בצבע אזהרה, ולחיצה עליו מתחברת שוב (בדרך כלל החלון נסגר מיד, כי ההרשאה כבר ניתנה). עד אז הכול נשמר בטלפון.
- **בממשק:** תפריט ← "חיבור ל־Google Drive" ← Client ID (פעם אחת) ← התחברות ← בחירת תיקיית הכספת (בורר תיקיות, בלי האפשרות לבחור את כל ה־Drive) ← סנכרון ראשון. "ניתוק": מה שכבר ב־Drive ולא השתנה מוסר מהטלפון, ומה שעוד לא נשלח נשאר (`vault.forgetRemote`), כדי שחיבור מחדש לא יעלה כפילויות.
- **נבדק בדפדפן** (375×812, Drive מדומה בדף, בלי Google): חזרה מ־Google בדף כולו (הטוקן נאסף, הבורר נפתח), בורר תיקיות, סנכרון ראשון (`.obsidian` דולג), עריכה ומסמך חדש בתיקייה חדשה עולים, טוקן שפג מסמן את הכפתור, ניתוק. **לא נבדק מול Google אמיתי** (צריך Client ID) **ולא בטלפון אמיתי**.

### הגדרה חד־פעמית ב־Google Cloud (המשתמש עושה, בחשבון שלו)

1. https://console.cloud.google.com ← פרויקט חדש (למשל "Tali Mobile").
2. APIs & Services ← Library ← **Google Drive API** ← Enable.
3. OAuth consent screen: סוג **External**, שם האפליקציה, המייל שלך. ב־Scopes: `.../auth/drive`. ב־**Test users**: להוסיף את חשבון ה־Google שבו הכספת. משאירים במצב **Testing** (בלי אימות של Google; מתאים לשימוש אישי).
4. Credentials ← Create credentials ← **OAuth client ID** ← סוג **Web application**:
   - Authorized JavaScript origins: הכתובת שבה האפליקציה רצה, למשל `http://localhost:8090` לבדיקה במחשב, וכתובת ה־HTTPS הקבועה לטלפון.
   - Authorized redirect URIs: אותה כתובת עם `/oauth.html`, למשל `http://localhost:8090/oauth.html`.
5. מעתיקים את ה־Client ID (`…apps.googleusercontent.com`) ומדביקים באפליקציה בפעם הראשונה. זה לא סוד (אין client secret באפליקציה).

**למה `drive` ולא `drive.file`:** `drive.file` רואה רק קבצים שהאפליקציה עצמה יצרה, ולא את הכספת הקיימת. `drive` נותן גישה לכל ה־Drive של החשבון; בפועל האפליקציה נוגעת רק בתיקייה שנבחרה. במצב Testing Google מציג אזהרה "האפליקציה לא אומתה" בהתחברות; זה צפוי.

**הכתובת (מ־22.11.2026): https://taliwrite.netlify.app/app/** — Netlify (האתר `taliwrite`) בונה אותה מ־`main` בכל push (`netlify.toml`). ב־Google Cloud: JavaScript origin `https://taliwrite.netlify.app`, Redirect URI `https://taliwrite.netlify.app/app/oauth.html`. בחשבון Netlify יש מכסת קרדיטים חודשית וכל build עולה ממנה: שינוי בתיעוד בלבד אפשר לדחוף עם `[skip netlify]` בהודעת ה־commit.

**לטלפון צריך כתובת HTTPS קבועה** (Google לא מקבל http חוץ מ־localhost, ו־PWA צריך HTTPS). ראו "אחסון באינטרנט" בהחלטות הפתוחות.

## החלטות פתוחות, והמלצה

1. **סנכרון: הוחלט Google Drive (22.11.2026), מומש למעלה.** ההמלצה המקורית: **local-first עם סנכרון קבצים למקום שבו הכספת כבר נמצאת**, בלי שרת משלנו. הטלפון שומר עותק מלא ועובד בלי רשת; המנוע כבר בנוי, וחסר רק מתאם (`list/read/write/remove`).
   - אם הכספת ב־**Google Drive** (כך נראה מההתנגשויות בדסקטופ): מתאם Google Drive API. דרוש Client ID של Google Cloud (OAuth) שהמשתמש יוצר פעם אחת. `md5Checksum` של Drive משמש כ־`rev`.
   - חלופות: Dropbox (אותו מבנה), WebDAV (Nextcloud/NAS), או מאגר Git פרטי לכספת (`sha` כ־`rev`, היסטוריה מלאה, אבל דורש token).
   - לא מומלץ: שרת סנכרון משלנו (תחזוקה, אבטחה, עלות).
2. **תשתית:** המלצה: PWA עכשיו (מתקינים מהדפדפן, עדכון מיידי, אותו קוד), ועטיפה ב־**Capacitor** רק אם יידרש קובץ התקנה לחנות או גישה ישירה לתיקייה בטלפון. אותו `mobile/www` נכנס ל־Capacitor כמו שהוא.
3. **התנגשויות:** מומש "שומרים את שתיהן" (הכי בטוח, ועקבי עם הדסקטופ). מיזוג אוטומטי ברמת שורה אפשר בהמשך, אבל רק למקרים שבהם השינויים לא חופפים.
4. **אחסון באינטרנט:** `website/` מפורסם ב־Netlify. אפשר לפרסם גם את `mobile/www` (למשל בכתובת `/app`); זה משנה את `netlify.toml` ולכן לא נעשה בלי אישור.
